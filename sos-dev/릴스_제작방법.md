# 앱 소개 릴스 제작 방법 (실제 앱 화면 녹화 + 나레이션 템포 편집)

공동육아 SOS 릴스를 만든 방법을 정리했어요. 웹앱이면 어느 앱이든 같은 순서로 만들 수 있어요.
결과물은 세로 1080×1920, 30fps, 25~30초 MP4이고 소리는 없어요. 음악과 나레이션은 캡컷·브루에서 얹어요.

---

## 0. 한눈에 보기

```
① 기획: 바이럴 4원칙 + 제목/첫 문장/엔딩
② 대본: 나레이션 문장 → 음절 수로 장면 길이 계산
③ 녹화: Playwright로 실제 앱을 자동 조작하며 '느린 시간'으로 촬영 (애니메이션까지 그대로)
④ 보조 장면: 단톡방(카톡 느낌) 같은 장면은 HTML로 만들어 프레임 렌더
⑤ 편집: 프레임마다 카메라(확대/이동) · 자막 · 전환을 합성 → JPG 프레임
⑥ 인코딩: ffmpeg로 MP4 + 대본 TXT + 자막 SRT
```

준비물: Node.js, Playwright(Chromium), ffmpeg. 실제 서비스 데이터 대신 **테스트 서버(예: Firebase 에뮬레이터)에 가짜 데이터**를 넣어 촬영해요. 실제 사용자 정보가 영상에 나오면 안 돼요.

## 1. 기획 규칙

### 바이럴 릴스 4원칙 (기획할 때 이것부터 체크)

**1. 보편성: 얼마나 많은 사람의 머릿속에 있는 개념을 쓰느냐**
- 예) "인물사진 잘 찍는 방법" → 인물사진을 찍고 싶은 사람만 봐요.
- 예) "여자친구 사진 잘 찍는 방법" → 여자친구가 있는 모든 남성이 봐요.
- 기능이나 도구 이름이 아니라 **사람과 상황**으로 대상을 불러요.
- 공동육아 SOS: "공동육아 앱" ✕ → **"오늘도 독박육아하는 엄마들에게"** ○

**2. 실용성: 정보성 콘텐츠**
- 보고 나서 "이거 쓸모 있다"가 남아야 저장하고 공유해요.
- 공동육아 SOS: 단톡방에 말 안 꺼내고도 모임을 만드는 방법

**3. 즉시성: 정보의 난이도가 낮을수록, 얼마나 쉽고 빠르게 해볼 수 있느냐**
- 예) "다이소에서 3천원만 투자하면 디퓨저 3병을 만들 수 있어요"
- 쉽고 빠를수록 필요한 사람에게 바로 공유해요.
- 공동육아 SOS: 링크 클릭 → 크롬·사파리로 열기 → 홈 화면에 추가하면 끝. 가입·다운로드 없음, 30초

**4. 단순성: 먼저 이해해야 좋아하든 공유하든 저장하든 해요**
- 한 번에 쉽게 해석돼야 해요. 설명이 필요한 순간 넘겨요.
- 공동육아 SOS: **"말 대신 SOS 꾹"** 한 줄로 이해

### 릴스 이론: 세 군데를 놓치면 안 돼요
| 구간 | 놓치면 | 하는 법 | 공동육아 SOS 예 |
|---|---|---|---|
| **① 제목** (표지·첫 화면 큰 글자) | 집중력을 잃어요 | 보편적인 대상을 직접 불러요 | 오늘도 독박육아하는 엄마들에게 |
| **② 첫 문장** (0~2초) | 관심을 잃어요 | 기능 말고 감정·상황부터 꺼내요 | 아니 진짜, 오늘도 독박육아! |
| **③ 엔딩** | 전환(행동)을 잃어요 | 행동 하나만 시켜요 (링크, 저장, 공유 중 하나) | 단톡방에 링크만 던져요 👇 (프로필 링크) |

### 표지 제목 만들 때 참고
- "오늘도 ○○하는 □□들에게" (대상 + 공감 상황)
- "○○ 탈출, 30초 세팅법" (즉시성)
- "□□한테 이 영상 보내세요" (공유 유도)
- 캡션 첫 줄도 제목처럼 써요. 피드에서 그 줄만 보여요.

### 흐름 공식 (문제 → 해결 → 결과 → 행동)
1. 공감 훅 (강)
2. 문제 장면: 하고 싶은데 못 하는 순간 (약) — 예) 단톡방에 쓰다가 지우기
3. 해결 ① 핵심 동작 (중)
4. 결과가 보이는 순간, 잠깐 멈춤 (약)
5. 해결 ② 클라이맥스 (강)
6. 결과 + 앱 고유 애니메이션 (약)
7. 엔딩 CTA (강)

## 2. 템포 규칙 (실패에서 배운 것)

| 시도 | 문제 | 고친 방법 |
|---|---|---|
| v1 캡처를 이어 붙임 | 슬라이드쇼 같고 광고 같음 | 실제 앱을 **움직이는 그대로 녹화** |
| v2 터치마다 확대·번쩍 | 정신없고 내용이 안 들어옴 | 효과는 **강한 순간 2~3번만** |
| v3~4 자막만 | 길게 읽혀서 나레이션과 안 맞음 | **나레이션 대본 먼저**, 장면 길이를 대본에 맞춤 |
| v5 긴 대본 | 녹음하면 영상보다 말이 김 | 문장을 짧게, 장면 시간은 넉넉하게 |

- 강·약·중·약·강처럼 **템포를 섞어요.** 계속 빠르면 지치고, 계속 느리면 넘겨요.
- 결과가 보이는 순간(완료 표시, 숫자 증가, 참석 3명)에서 **0.6~0.7초 멈춰요.**
- 자막은 **한 장면에 하나**, 단계 번호(①②③)로 순서를 보여 줘요.
- 확대는 결과를 보여 줄 때만 **천천히** 해요.

### 나레이션 길이 계산
- 차분한 말투: 1초에 **4.5~5음절**, 텐션 높은 말투: **6음절**
- 장면 길이 = `음절 수 ÷ 속도 + 0.3~0.4초(숨)` 이고, 장면마다 최소 길이(2.4~3.4초)를 둬요.
- 녹음하기 편하려면 **음절 기준 4.5로 계산하고 문장은 짧게** 써요.

최종 대본 예 (28.7초):
```
[0.0s] 아니 진짜, 오늘도 독박육아!
[2.8s] 단톡방에 "모임 하실 분~" 쓰려다가,
[6.1s] 답 없으면 민망해서 지웠죠 ㅠㅠ
[9.0s] 그래서 말 대신 SOS 꾹!
[12.0s] 어머, 나만 독박이 아니었네?!
[15.2s] 용기 낸 한 명이 모임 열고,
[18.6s] 다들 참석만 꾹!
[21.4s] 오늘 독박, 같이 탈출!
[23.8s] 가입 없이, 단톡방에 링크만 던져요!
```

## 3. 실제 앱 녹화 (핵심 기술)

헤드리스 브라우저는 실시간으로 고화질 프레임을 충분히 못 찍어요(1080×1920은 초당 ~8장).
그래서 **앱 안의 시간을 4배 느리게** 흐르게 하고 찍은 뒤, 프레임 시각을 ÷4 해서 원래 속도로 돌려요.

### 3-1. 브라우저 설정
```js
const ctx = await browser.newContext({ viewport: { width: 360, height: 640 }, deviceScaleFactor: 3 });   // 폰 크기 × 3 = 1080×1920
```

### 3-2. 앱 시간 느리게 + 터치 표시 (페이지 로드 전에 주입)
```js
await ctx.addInitScript(() => {
  const R = 0.25;                                          // 4배 느리게
  const pn = performance.now.bind(performance), st = pn();
  performance.now = () => st + (pn() - st) * R;           // JS 애니메이션(rAF) 시간
  const raf = requestAnimationFrame.bind(window);
  window.requestAnimationFrame = cb => raf(() => cb(performance.now()));
  // 누른 곳에 하얀 동그라미가 퍼지는 터치 표시
  addEventListener('pointerdown', e => { const d = document.createElement('div');
    d.style.cssText = `position:fixed;left:${e.clientX-22}px;top:${e.clientY-22}px;width:44px;height:44px;border-radius:50%;
      background:rgba(255,255,255,.45);border:3px solid #fff;z-index:2147483647;pointer-events:none;transition:transform .45s,opacity .45s`;
    document.documentElement.appendChild(d);
    requestAnimationFrame(() => { d.style.transform = 'scale(1.8)'; d.style.opacity = '0'; });
    setTimeout(() => d.remove(), 2400); }, true);
});
```

### 3-3. CSS 애니메이션도 느리게 + 프레임 촬영 루프
```js
const cdp = await ctx.newCDPSession(page);
await cdp.send('Animation.enable');
await cdp.send('Animation.setPlaybackRate', { playbackRate: 0.25 });   // 페이지 이동 후에도 다시 호출
let rec = true, n = 0, t0 = Date.now() / 1000;
(async () => { while (rec) {
  const v = (await cdp.send('Page.getLayoutMetrics')).cssVisualViewport;   // 스크롤 위치
  const r = await cdp.send('Page.captureScreenshot', { format: 'jpeg', quality: 88, optimizeForSpeed: true,
    clip: { x: v.pageX, y: v.pageY, width: 360, height: 640, scale: 3 } });   // 1080×1920
  const ts = Date.now() / 1000 - t0;
  fs.writeFileSync(`raw/${String(n++).padStart(5,'0')}_${ts.toFixed(3)}.jpg`, Buffer.from(r.data, 'base64'));
} })();
```
> `Page.startScreencast`는 화면 크기(360×640)로만 나와서 쓰지 않았어요. `captureScreenshot`에 `clip.scale: 3`을 줘야 고화질이 나와요.

### 3-4. 조작 스크립트 (대기 시간은 ×4)
```js
const w = ms => page.waitForTimeout(ms * 4);
const taps = [];   // 편집 때 카메라가 따라갈 터치 위치
const tap = async (sel, wait = 350) => { const b = await page.locator(sel).first().boundingBox();
  const x = b.x + b.width / 2, y = b.y + b.height / 2; taps.push([Date.now()/1000 - t0, x, y]);
  await page.mouse.move(x, y, { steps: 4 }); await page.mouse.down(); await page.waitForTimeout(70); await page.mouse.up(); await w(wait); };

await tap('[data-slot="14시"]', 250);
await tap('.sos-btn', 1200);
await page.keyboard.type('장소: 키즈룸\n놀이: 비눗방울', { delay: 160 });   // 타이핑도 느린 시간 기준
// 다른 사람 반응은 테스트 서버 데이터를 직접 바꿔서 실시간으로 쌓이게 해요
for (const u of ['u0','u2','u4']) { await updateVote(u); await w(700); }
```
- 스크롤은 `scrollIntoView({behavior:'smooth'})` 대신 **느린 시간에 맞춘 직접 스크롤 함수**를 쓰세요. 기본 smooth 스크롤은 실제 시간 기준이라 너무 빨라 보여요.
- 입력창에 기본 글(틀)이 있으면 먼저 `fill('')`로 비워요.
- 녹화 시각과 터치 위치를 `log.json`으로 저장해 두면 편집이 쉬워요.

### 3-5. 30fps로 고르게 맞추기
```python
ts = [float(f.split('_')[1][:-4]) / 4 for f in files]   # ÷4 = 영상 시간
for i in range(int(ts[-1]*30)):                          # 30fps 프레임마다 가장 가까운 앞 장면
    j = bisect.bisect_right(ts, i/30) - 1
    os.link('raw/'+files[j], f'seq/{i:05d}.jpg')
```

## 4. 보조 장면 (단톡방 등)

실제 메신저는 녹화할 수 없으니 **HTML로 비슷하게** 만들고 `render(t)` 함수로 시간별 상태를 그려요.
- 메시지 하나씩 등장 → 입력창에 한 글자씩 타이핑(키보드 키 눌림 표시) → 망설임 → 한 글자씩 지우기
- **실제 서비스 로고나 이름은 쓰지 않아요.** 색과 배치만 비슷하게 해요.

```js
for (let i = 0; i < DUR * 30; i++) { await page.evaluate(t => render(t), i / 30);
  await page.screenshot({ path: `chat/${String(i).padStart(5,'0')}.jpg`, type: 'jpeg', quality: 92 }); }
```

## 5. 편집 합성 (comp.html + edit.cjs)

1080×1920 HTML 한 장에 레이어를 쌓고, 프레임마다 값만 바꿔 스크린샷을 찍어요.
- `#cam > img`: 녹화 프레임. `transform: translate() scale()`로 카메라 확대·이동
- `#f2`: 장면 전환 때 이전 화면을 겹쳐 서서히 사라지게(크로스페이드)
- `#hook`: 첫 장면 큰 글자 (배경은 앱 화면을 흐리게)
- `#cap`: 자막 말풍선 (불투명 배경, 노란 테두리, 강조는 `<b>` 노란색)
- `#end`: 엔딩 (앱 아이콘 + 마스코트 + CTA + 콩콩 뛰는 👇)
- `#flash`: 강한 장면 시작 때만 0.15초 하얀 번쩍

### 장면 정의 = 나레이션 문장
```js
const N = [
  { text: '아니 진짜, 오늘도 독박육아!', src: 'hook', tone: 'strong' },
  { text: '단톡방에 "모임 하실 분~" 쓰려다가,', src: 'chat', a: 0, b: 2.6, min: 2.8 },
  { text: '그래서 말 대신 <b>SOS 꾹!</b> 🆘', src: 'app', a: 4.6, b: 7.4, tone: 'mid', min: 3.0 },
  // a~b = 녹화 원본의 어느 구간을 보여 줄지(초), min = 최소 장면 길이
  { text: '가입 없이,|단톡방에 <b>링크만</b> 던져요! 👇', src: 'end' },   // | = 자막 나눔
];
const syl = s => (s.replace(/<[^>]+>/g,'').match(/[가-힣]|[A-Za-z]{1,3}/g) || []).length;
n.dur = Math.max(n.min || 0, syl(n.text) / RATE + GAP);   // RATE 4.5, GAP 0.4
```
- 장면 안에서 원본은 0.8~1.7배 속도로 흐르고, 남는 시간은 **마지막 화면에서 멈춰요**(결과를 보여 주는 홀드).
- 카메라 목표는 `FOCUS`(원본 시각 구간 → 배율, 중심)로 정하고, 매 프레임 `cs += (목표 - cs) * 0.06`(약) / `0.1`(강)으로 **부드럽게 따라가요.**
- 확대 배율은 1.12~1.28 정도. 그보다 크면 어지러워요.
- 자막은 강한 장면만 살짝 커졌다 제자리(0.9→1.0), 나머지는 부드럽게 나타나요.

같이 저장하는 파일:
- `narration.txt`: 녹음용 대본 (시작 시각 포함)
- `narration.srt`: 자막 파일. 캡컷·브루에 불러와 AI 목소리(TTS)로 바로 쓸 수 있어요

## 6. 인코딩
```bash
ffmpeg -y -framerate 30 -i out/%05d.jpg -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -movflags +faststart reel.mp4
```
표지 이미지는 첫 장면 프레임(예: `out/00030.jpg`)을 쓰면 돼요.

## 7. 검수 체크리스트
- [ ] 프레임 10~12장을 한 장에 모아(콘택트 시트) 장면마다 확인
- [ ] 자막이 다른 글자와 겹쳐 안 읽히는 곳 없음 (자막 배경 불투명)
- [ ] 마스코트·팝업 같은 애니메이션이 이상한 위치에서 멈춘 프레임 없음
- [ ] 테스트 데이터만 나옴 (실명, 실제 방 이름, 연락처 없음)
- [ ] 장면당 자막 1개, 나레이션을 소리 내어 읽어 봐서 시간 안에 들어감
- [ ] 첫 2초에 공감 문구, 마지막에 행동 하나

## 8. 올릴 때
- 음악: 잔잔하게 시작해서 중간에 비트가 살아나는 곡 → 강약이 살아요
- 나레이션: 직접 녹음(대본 보며 자막 타이밍에 시작) 또는 SRT → TTS (밝은 목소리, 1.1~1.2배)
- 영상 안에 자막이 있으니 앱의 자동 자막은 끄기
- 캡션 첫 줄 = 제목처럼 ("오늘도 독박육아 중인 엄마들 🙋‍♀️")
- 프로필 링크에 앱 주소, 댓글에 빨리 답하기

## 9. 다른 앱에 쓰려면 바꿀 것
1. **대본 `N`**: 4원칙에 맞춰 문제 → 해결 → 결과 → 행동으로 다시 써요
2. **녹화 스크립트**: 앱 주소, 셀렉터(`tap('...')`), 테스트 데이터 넣는 부분
3. **보조 장면 HTML**: "문제 상황"을 보여 주는 화면 (메신저, 메모, 엑셀 등)
4. **FOCUS**: 결과가 보이는 위치(앱 좌표 360×640 기준)
5. **엔딩**: 아이콘, 이름, CTA 문구

실사 영상(사람·장소)은 이 방법으로는 못 만들어요. 필요하면 AI 영상 툴(Kling, Runway, Veo)로 3~4초를 만들어 첫 장면만 바꿔 끼우세요.
