# 공동육아 SOS 달력 작업기록 (2026-10-04)

## 목표 사거리
공개 서비스로 키울 수도 있음. 우선 지인 베타 테스트.

## 현재 구조
- `sos/` 폴더에 정적 웹앱 (HTML/CSS/JS). 윤하 성장노트(`/index.html`)와 완전히 분리.
- 데이터: Firestore `rooms/{roomKey}` (방 이름), `rooms/{roomKey}/marks/{id}` (🆘/✋ 표시)
- roomKey = SHA-256(방코드 + ":" + 비밀번호). 비밀번호는 어디에도 저장 안 함.
- 로그인: Firebase 익명 로그인 (내 표시만 지우기 위한 구분용)
- `config.js`가 비어 있으면 체험 모드(localStorage).

## 처리 주체 분류
- 코드 칸: 날짜, 🆘/✋ 종류, 비밀번호 확인, 지난 날짜 판정, 공유 문구 만들기
- AI 칸: 없음 (일부러 뺌)
- 사람 칸: 누가 실제로 돌봐줄지 결정 → 단톡방에서 대화로

## 결정된 사항과 이유
- 기능은 "달력 + 버튼 두 개"만. 플랫폼처럼 기능이 많으면 안 씀 (사용자 판단).
- 확정·고마움 기록·채팅·AI는 뺌. 베타에서 요청이 나오면 하나씩.
- 푸시 알림 대신 "📣 단톡방에 알리기" 공유 버튼. 웹앱 알림은 제약이 많고, 사람들은 이미 단톡방을 봄.
- 윤하 성장노트 Firebase 프로젝트와 분리. 가족 기록과 공개 앱 데이터를 섞지 않기 위해.
- 체험 모드에서 Firebase 로드 실패 시 몰래 로컬로 바꾸지 않고 오류 표시 (공유되는 줄 착각 방지).

## 추가: 방 지우기 · 사용 방법
- 방장(방을 만든 휴대폰)은 '🗑 방 지우기' → 확인 팝업("방을 지우면 기록도 다 사라져요") → 방 안 기록 위치를 먼저 모으고, 방에 '지워짐' 표시 후 기록을 실제 삭제
  - 방장 확인: 만들 때 이 휴대폰에만 방장 열쇠(owner), 서버에는 지문(oh). 열쇠 없이 만든 예전 방은 들어온 사람 누구나 지울 수 있음
  - 서버 규칙: 지워진 방은 읽기·쓰기 불가, 지워진 방의 기록만 삭제 가능
- 초대받은 사람은 '🚪 이 휴대폰에서 방 빼기'(내 목록에서만)
- 비밀번호 화면에 사용 방법: 단톡방·밴드·당근 모임·소모임 옆에 붙여 쓰는 도구, 방 만들기 → 초대 링크 + 비밀번호 공유 → SOS 예약 → 모임
- 결정: "기록도 다 사라져요" 문구가 사실이 되도록, 숨기기만 하지 않고 실제로 지우게 함

## 추가: 사람이 많아질 때 대비
- 멈춤 안내: 무료 사용량 초과(resource-exhausted)·연결 끊김이면 화면 맨 위에 빨간 안내 띠. SOS 예약 버튼도 막고 "지금은 SOS 예약을 할 수 없어요"
  - 진짜 원인: 예전엔 에러/오프라인 때 SOS가 '0명'으로 그려져 "SOS 없음"으로 오해할 수 있었음
  - Firebase가 오프라인일 때 보내는 빈 임시 데이터(fromCache)는 무시(serverOnly). 8초 안에 서버 답이 없으면 연결 안내
- 읽기 줄이기: 홈 모임은 오늘 이후만(예전: 최근 300개), 모임 페이지는 지난 30일부터, SOS는 오늘~1주일치만(예전: 지난 29일부터), 방 지워짐 확인은 브라우저 열 때 한 번
- 사용자 요청: 모임·SOS 날짜는 오늘부터 1주일(7일)까지만 고르기 (BOOK_DAYS). 서버 규칙으로는 막지 않음(화면에서만)
